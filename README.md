# engineer-career-map

未経験からエンジニアへの転職を目指す人向けの学習資料です。
「どんな仕事があるか」から「転職までの道のり」まで、全体像を地図のように見せます。

**公開ページ**：https://motoki0805.github.io/engineer-career-map/ （GitHub Pages。`main` ブランチの直下を公開）

このREADMEには、資料の構想と決まっていることをまとめています。別のセッション（AIとの別の会話を含む）で続きを作るときは、まずここを読んでください。

## 目的と前提

- **読む人**：エンジニアへの転職を目指す、プログラミング未経験の人（少人数）。
- **作る人**：現役のWebエンジニア。管理者として学習に伴走する。資料は、説明するときに画面で見せながら使う。
- **伝えたいこと**
  - いきなり「コードを書けるようになる」を目標にしない。
  - まず、エンジニアの仕事と、サービスができるまでの全体像を見せる。
  - その中で「コーディングは全体のこの部分」と位置づける。
  - 最終的には、身の回りや前職の課題を見つけて、それを解決するものを完成させる（ポートフォリオ）。
- **学習サービス**：基礎はProgateで学ぶ想定。

## 構成

各章は、**1つの問いに答える**形にする。工程と知識のように種類の違う話を、1つの章や表に混ぜない。

| 章 | タイトル | 答える問い | 状態 | ファイル |
|---|---|---|---|---|
| 1 | プログラマーの仕事 | どんな仕事があるのか？ | 完成（モック） | [chapter1.html](chapter1.html) |
| 2 | Webサービスができるまで | どういう流れで作るのか？ | 未着手 | — |
| 3 | 必要な知識 | 何を身につけるのか？ | 未着手 | — |
| 4 | 転職までの道のり | どう進めばいいのか？ | 未着手 | — |

- 1〜3章は「知る」、4章は「動く」。仕事 → 作り方 → 知識と範囲を絞っていき、4章で「自分はどう進むか」に着地させる。
- **1章はWebに絞らない。** こういう職種や働き方がある、と紹介するだけにする。
- **2〜4章はWebを例にする。** 2章の冒頭に「工程はどの分野でも共通。ここではWebを例に説明する」と入れる。

### 1. プログラマーの仕事
| 小項目 | 中身 |
|---|---|
| 1-1 分野 | 何を作る仕事か。Web、スマホアプリ、業務システム、組み込み、ゲーム、データ・AI。作るものの例と、よく使う言語 |
| 1-2 職種 | 何を担当するか。SE、プログラマー、インフラエンジニア、QA、PM |
| 1-3 会社での働き方 | 自社開発、受託開発、SES、社内SE。良いところ・気をつけること・未経験からの入りやすさ |
| 1-4 フリーランスの位置づけ | 1-3と同じ形で、フリーランスの働き方（仕事の取り方）を並べる。エージェント経由、クラウドソーシング、直接契約、知人からの紹介 |

- 分野（何を作るか）と職種（何を担当するか）は別の軸なので、1つにまとめない。
- 1-3（会社の形）と1-4（フリーランス）も軸が違うので、別の小項目にしている。
- 1-4の最後に「現役フリーランスの体験談（その場で話す）」の枠を置く。

### 2. Webサービスができるまで
小項目は工程そのもの。各工程に「何をするか・何ができあがるか・誰が担当するか（1-2の職種名を使う）」を書く。

| 小項目 | 何をするか |
|---|---|
| 2-1 企画 | 課題を見つけて、何を作るか決める |
| 2-2 設計 | 画面とデータの形を決める |
| 2-3 実装 | コードを書く（★コーディングはここ） |
| 2-4 テスト | 思いどおりに動くか確かめる |
| 2-5 公開 | インターネットに出す |
| 2-6 運用・改善 | 使われ方を見て直す。また2-1に戻る |

### 3. 必要な知識
| 小項目 | 中身 |
|---|---|
| 3-1 知識マップ | 学ぶ知識を7分野に分けて、カードで1行ずつ説明する |
| 3-2 工程×知識の対応表 | 2章の工程（縦）× 3-1の分野（横）。主に使うところに印を付ける |

3-1の7分野：
- **土台**：Webの仕組み（ブラウザ、サーバー、HTTP）
- **設計**：要件の考え方、画面設計、データ設計
- **フロントエンド**：HTML/CSS、JavaScript
- **バックエンド**：サーバー側の言語、フレームワーク
- **データベース**：SQL
- **インフラ**：サーバー、デプロイ
- **道具とセキュリティ**：Git/GitHub、エディタ、ターミナル、セキュリティの基本

- 「設計」を知識の分野に入れるのは、対応表の企画・設計の行が空にならないようにするため。
- 対応表で伝えたいこと：コーディングの知識（フロント・バック・DB）は実装とテストに集中していて、ほかの工程では別の知識を使う。つまり、コードが書けるだけではサービスは完成しない。
- 3-1に職種のラベルは付けない（1章の職種はWeb限定ではないため、軸が合わない）。

### 4. 転職までの道のり
| 小項目 | 中身 |
|---|---|
| 4-1 学ぶ順番 | 段階ごとのロードマップ。どこまでがProgateの範囲かを帯で示す |
| 4-2 ポートフォリオ | 課題から作る理由。評価されるポイント（なぜ作ったか、技術を選んだ理由、苦労して解決したこと） |
| 4-3 転職活動 | 書類、面接、会社の見極め方 |

- 転職が目的なので、ゴールはProgateの修了ではなく、人に見せられる成果物を作ること。

## デザインの決まりごと

`chapter1.html` が見本。2章以降も同じ見た目にそろえる。

- **モックでも、デザインとレイアウトは本番品質で作る。** モックは「機能は省くが、見た目を判断するためのもの」。
- **明るい1テーマに固定する。** ダークモードには切り替えない。未経験の人が構えずに読める、明るく親しみやすい雰囲気にする。
- **PC表示を優先する。** スマホ表示は今のところ確認しない。
- **書体**：見出しは Zen Maru Gothic、本文は Noto Sans JP（Google Fonts）。
- **色**：背景はごく薄い青みのグレー、メインは青（`#3b5bdb`）。フリーランスなど目立たせたいものはオレンジ（`#f76707`）。分野ごとのアイコンは6色で塗り分け。
- **部品**
  - 角の丸い白いカード（影は薄く）を中心に並べる。
  - アイコンはインラインSVG（線のアイコン）。
  - 比較するものは、同じ形のカードを横に並べる。各カードに「＋良いところ」「！気をつけること」「未経験からの入りやすさ（3段階のバーと言葉）」。
  - 補足は「i」アイコン付きの一言で添える。
- **ページの流れ**：上部に「1〜4章のうち今どこか」の表示 → 章タイトルと説明、右に小項目の入口カード → 小項目ごとのセクション → 最後に次の章への案内。
- **確認**：PCの画面幅で表示を確認してから公開する。文字の途中での折り返しや、カードごとの段のずれに注意する。
