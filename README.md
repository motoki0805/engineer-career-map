# engineer-career-map

未経験からエンジニアへの転職を目指す人向けの学習資料です。
「どんな仕事があるか」から「転職までの道のり」まで、全体像を順番に見せます。

**公開ページ**：https://motoki0805.github.io/engineer-career-map/ （GitHub Pages。`main` ブランチの直下を公開）

このREADMEには、資料の構想と決まっていることをまとめています。別のセッション（AIとの別の会話を含む）で続きを作るときは、まずここを読んでください。

## 目的と前提

- **読む人**：エンジニアへの転職を目指す、プログラミング未経験の人（少人数）。
- **作る人**：現役のWebエンジニア。管理者として学習に伴走する。資料は、説明するときに画面で見せながら使う。
- **伝えたいこと**
  - いきなり「コードを書けるようになる」を目標にしない。
  - まず、エンジニアの仕事と、サービスができるまでの全体像を見せる。
  - その中で「コーディングは全体のこの部分」と位置づける。
  - 最終的には、身の回りや前職の課題を見つけて、それを解決するものを完成させる（ポートフォリオ）。
- **学習サービス**：基礎はProgateで学ぶ想定。

## 構成

各章は、**1つの問いに答える**形にする。工程と知識のように種類の違う話を、1つの章や表に混ぜない。

| 章 | タイトル | 答える問い | 状態 | ファイル |
|---|---|---|---|---|
| 1 | プログラマーの仕事 | どんな仕事があるのか？ | 完成 | [chapter1.html](chapter1.html) |
| 2 | Webサービスができるまで | どういう流れで作るのか？ | 完成 | [chapter2.html](chapter2.html) |
| 3 | 必要な知識 | 何を身につけるのか？ | 未着手 | — |
| 4 | 転職までの道のり | どう進めばいいのか？ | 未着手 | — |

- 1〜3章は「知る」、4章は「動く」。仕事 → 作り方 → 知識と範囲を絞っていき、4章で「自分はどう進むか」に着地させる。
- **1章はWebに絞らない。** こういう職種や働き方がある、と紹介するだけにする。
- **2〜4章はWebを例にする。** 1章から急にWebに絞られて唐突にならないよう、2章の「はじめに」で、なぜWebを例にするかを書く（未経験の求人が多い、Progateで学べてパソコン1台で始められる、URLで人に見せられるのでポートフォリオにしやすい）。
- **章のつなぎを書く。** 各章の最後に「まとめ」を置き、次の章の問いにつなぐ。特に3章のまとめでは「全体が分かった。じゃあ自分はどう進む？」と4章につなぐ。
- **資料の入口は目次（`index.html`）。** 4つの章と、それぞれが答える問いを1枚で見せる。
- **「地図」という言い方は使わない。**（リポジトリ名の map はそのまま）

### 1. プログラマーの仕事
| 小項目 | 中身 |
|---|---|
| はじめに | この章で見ること。各項目への入口カード |
| 1-1 分野 | 何を作る仕事か。Web、スマホアプリ、業務システム、組み込み、ゲーム、データ・AI。作るものの例と、よく使う言語。Web・スマホアプリ・業務システムには「詳細」（画面の画像つきの説明）がある |
| 基礎知識 仕事の流れ | V字モデル。要件定義 → 基本設計 → 詳細設計 → 実装 → 単体テスト → 結合テスト → システムテスト → 受け入れテスト。左で決めて、右で確かめる。上流工程・下流工程 |
| 1-2 職種 | 何を担当するか。SE、プログラマー、インフラエンジニア、QA、PM。各職種が担当するフェーズ（V字の8工程）を色の帯で示す |
| コラム AIで変わったこと | 変わったこと・求められること・変わらないこと。未経験者の採用状況（レバテック「IT人材白書2026」） |
| 1-3 会社での働き方 | 自社開発、受託開発、SES、社内SE。良いところ・気をつけること・未経験からの入りやすさ |
| 1-4 フリーランス | 1-3と同じ形で、フリーランスの働き方（仕事の取り方）を並べる。エージェント経由、クラウドソーシング、直接契約、知人からの紹介 |
| まとめ | この章のポイント3つと、次の章への案内 |

- 分野（何を作るか）と職種（何を担当するか）は別の軸なので、1つにまとめない。
- 1-3（会社の形）と1-4（フリーランス）も軸が違うので、別の小項目にしている。
- 「仕事の流れ」と「AIで変わったこと」は番号を付けない（付けると以降の番号がずれるため）。ラベルは「基礎知識」「コラム」。
- 1-4の最後に「現役フリーランスの体験談（その場で話す）」の枠を置く。
- 数字を載せるときは、出典が確かなものだけにし、出典を書く。
- 詳細の画像は、講師が作ったもの（職業訓練校で作ったサイト、実家の販売管理アプリ）。サイトの言語などの説明は口で話すので書かない。

### 2. Webサービスができるまで
工程を1つずつ小項目にするのではなく、まず全体の流れを見せてから、4つの段階に分けて見る。「決める・作る・確かめる」は、1章のV字で使った言葉にそろえる（左側＝決める、下＝作る、右側＝確かめる）。

| 小項目 | 中身 |
|---|---|
| はじめに | この章で見ること。なぜWebを例にするのか |
| 2-1 全体の流れ | 1枚の図で、企画から運用までを見せる。1章のV字との対応も示す（企画＝要件定義、設計＝基本設計・詳細設計、テスト＝4つのテスト。V字にない公開・運用を足す） |
| 2-2 決める | 企画・設計。課題を見つけて何を作るか決め、画面とデータの形を決める |
| 2-3 作る | 実装。コードを書く（★コーディングはここ） |
| 2-4 確かめる | テスト。思いどおりに動くか確かめる |
| 2-5 届けて、育てる | 公開・運用・改善。インターネットに出し、使われ方を見て直す。また2-2に戻る |
| まとめ | この章のポイント |

- 各段階に「何をするか・何ができあがるか・誰が担当するか（1-2の職種名）」を書く。
- 各段階に「AIが手伝えること／人がやること」を入れる。
- 章を通して1つの例（会議室の予約サイト）を使い、決めるところから育てるところまで追いかける。
- 2-2〜2-5は同じ形にそろえる：「やること・できあがるもの・例」の表と担当する職種 → 「AIが手伝えること／人がやること」→ 補足。
- V字にない「届けて、育てる」（公開・運用・改善）は青緑（`#1098ad`）で示す。

### 3. 必要な知識
| 小項目 | 中身 |
|---|---|
| はじめに | この章で見ること |
| 3-1 学ぶことの全体 | 学ぶ知識を7分野に分けて、カードで1行ずつ説明する |
| 3-2 段階×知識の対応表 | 2章の4段階（縦）× 3-1の分野（横）。主に使うところに印を付ける |
| まとめ | この章のポイント。「全体が分かった。じゃあ自分はどう進む？」と4章につなぐ |

3-1の7分野：
- **土台**：Webの仕組み（ブラウザ、サーバー、HTTP）
- **設計**：要件の考え方、画面設計、データ設計
- **フロントエンド**：HTML/CSS、JavaScript
- **バックエンド**：サーバー側の言語、フレームワーク
- **データベース**：SQL
- **インフラ**：サーバー、デプロイ
- **道具とセキュリティ**：Git/GitHub、エディタ、ターミナル、セキュリティの基本

- 「設計」を知識の分野に入れるのは、対応表の「決める」の行が空にならないようにするため。
- 対応表で伝えたいこと：コーディングの知識（フロント・バック・DB）は「作る」と「確かめる」に集中していて、「決める」「届けて、育てる」では別の知識を使う。つまり、コードが書けるだけではサービスは完成しない。
- AIの話として「AIツールの使い方」を入れる（8つ目の分野にするか、「道具とセキュリティ」に含めるかは未定）。
- 3-1に職種のラベルは付けない（1章の職種はWeb限定ではないため、軸が合わない）。

### 4. 転職までの道のり
| 小項目 | 中身 |
|---|---|
| 4-1 学ぶ順番 | 段階ごとのロードマップ。どこまでがProgateの範囲かを帯で示す |
| 4-2 ポートフォリオ | 課題から作る理由。評価されるポイント（なぜ作ったか、技術を選んだ理由、苦労して解決したこと） |
| 4-3 転職活動 | 書類、面接、会社の見極め方 |

- 転職が目的なので、ゴールはProgateの修了ではなく、人に見せられる成果物を作ること。
- AIの話として、課題から作ったポートフォリオが評価される（チュートリアルをなぞっただけの作品は評価されにくい）ことを入れる。

## デザインの決まりごと

`chapter1.html` が見本。2章以降も同じ見た目と作りにそろえる。

- **モックでも、デザインとレイアウトは本番品質で作る。** モックは「機能は省くが、見た目を判断するためのもの」。
- **明るい1テーマに固定する。** ダークモードには切り替えない。未経験の人が構えずに読める、明るく親しみやすい雰囲気にする。
- **PC表示を優先する。** 1440×900と1920×1080で確認する。スマホ表示は今のところ確認しない。
- **書体**：見出しは Zen Maru Gothic、本文は Noto Sans JP（Google Fonts）。日本語は文節で折り返す（`word-break: auto-phrase`）。
- **画面の形はスライド型（パワーポイントのイメージ）**
  - 上に章（1〜4章のうち今どこか）、左に項目のメニュー、右に1項目ずつ表示する。
  - 本文が収まらないときは、右の本文の枠の中だけスクロールする。画面全体はスクロールしない。
  - 「前へ」「次へ」は画面下のバーに固定し、どの項目でも同じ位置に出す。←→キーでも移動できる。
  - 本文は画面の幅いっぱいに使う（最大幅で制限しない）。自動で拡大・縮小するような重い仕組みは入れない。
- **どの項目も同じ骨組み**：ラベルとタイトル（右に一言の説明）→ カードや図 → 補足（「i」アイコン付きの一言）。各章は「はじめに」で始まり「まとめ」で終わる。
- **言葉をそろえる**：メニュー、各ページの見出し、「はじめに」の入口カードで、ラベル（「1-1」「基礎知識」「コラム」など）と名前を同じにする。
- **色の意味**
  - 背景はごく薄い青みのグレー。基本（ナビ・職種・会社など）は青（`#3b5bdb`）、AIは紫（`#7048e8`）、フリーランスや「動く」はオレンジ（`#f76707`）。
  - V字の工程だけは、設計＝青、実装＝黄みのオレンジ（`#e67700`）、テスト＝緑（`#0ca678`）で塗り分ける。1-2の担当フェーズと、2章の段階（決める・作る・確かめる）も同じ色。2章の「届けて、育てる」は青緑（`#1098ad`）。
  - 「＋良いところ」は青、「！気をつけること」は赤みのピンク（`#d6336c`）の印。
  - 分野ごとのアイコンは6色で塗り分け。
- **部品**
  - 角の丸い白いカード（影は薄く）を中心に並べる。カードは「アイコン＋見出し」から始め、角の丸み・アイコンの大きさ・見出しの大きさをそろえる。
  - アイコンはインラインSVG（線のアイコン）。
  - 比較するものは、同じ形のカードを横に並べる。各カードに「＋良いところ」「！気をつけること」「未経験からの入りやすさ（3段階のバーと言葉）」。説明の行数が違っても、カードの段の高さはそろえる。
  - 詳しい説明は「詳細」ボタンからモーダル（`<dialog>`）で出す。画像・どんなもの・よく使う言語。スマホの画面は端末の形の枠で囲む。
- **確認**：PCの画面幅で表示を確認してから公開する。文字の途中での折り返しや、カードごとの段のずれに注意する。

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | 目次。4つの章と、それぞれが答える問い |
| `chapter1.html` | 1章 プログラマーの仕事 |

- 1章ごとに1ファイル（`chapter2.html` …）にする。
- 外部から読み込むのはGoogle Fontsだけ。CSS・JS・アイコンはファイルの中に書く。JSは項目の切り替えとモーダルの開閉だけにとどめる。
- `main` にpushすると、GitHub Pagesに自動で反映される（1〜2分かかる）。
- 手元で確認するときは、リポジトリのフォルダで `npx -y live-server --port=5500 --open=chapter1.html` を実行すると、保存するたびに自動で再読み込みされる。
